# AC-03 の分離確認を Cake の方式に揃える

[Issue #32](https://github.com/tyask/mille/issues/32) の AC-03 を、既存の Free ストアと空の既定ブランチで検証する。静的デプロイで Native 分岐を作り、信頼済みの `main` と試験ソース、PR、現在 HEAD、デプロイ、分岐元、専用ブランチと endpoint、世代を照合する。Cake に沿って、確認済みの専用 DB の所有を照合したうえで、Native が注入する専用接続先を使うアプリを公開する。ロールのパスワードが同じ場合も、対象と接続先の前提を満たせば処理を進める。 [Cake のデプロイ・再利用・削除](https://github.com/tyask/Cake/blob/5975e5f20d9eb755d991b8725840feab0b778d65/scripts/preview/preview-service.ts#L50-L135)

注入された接続先や DB の所有マーカーが一致しない場合は後続の DB 操作と公開を停止する。同じ PR の更新は照合済みブランチ、endpoint、世代とデータを再利用する。終了時は所有を照合した専用資源を削除し、不在を確認する。管理用の資格情報は信頼済みの管理ジョブで使い、記録には識別子と結果を載せる。

ローカルのテストで接続先、所有、現在 HEAD の不一致時に停止することと、更新・削除の再試行時の照合を確認する。完全 SHA の独立レビュー、Cloud 検証、CI、正式 Preview を確認する。マージと一時切替は別途承認を得る。そのうえで試験 A/B のアプリに架空データを入れ、分離、同一 PR の HEAD 更新時の保持、クローズ・マージ後の自動削除を実環境で確認する。試験後に旧構成へ復旧し、常設 Preview と残存資源を確認する。AC-03 は証拠が揃った時点でチェックする。
