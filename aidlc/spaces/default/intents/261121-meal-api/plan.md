# P1b 献立APIの実装計画

P1aで追加したデータ基盤を使い、家族が共有ワークスペースで献立を記録・閲覧し、過去の献立を再利用できるAPIを実装する。

- 一覧・詳細・登録・更新・削除を追加する。日付範囲で一覧を取得し、古い版での更新・削除や、同じ日付・食事区分への重複登録を409で拒否する。
- 献立全体をコピーし、コピー先に独立した記録を作る。料理名の部分一致検索では、同じ料理を別の日に記録した場合も日付ごとに返す。
- 現在の利用資格と所属を確認し、書き込みには同一オリジンとIdempotency-Keyを要求する。同じキー・同じ内容の再送には24時間、元の成功応答を返し、同じキーで異なる内容は409にする。レスポンスは共有キャッシュに載せない。
- P1aのRepositoryと入力スキーマを再利用し、DB変更は追加マイグレーションで行う。献立画面と料理単位のコピー操作はP1cで扱う。

PGliteとHTTP契約テストで移行・権限・競合・再送・入力上限を確認する。最終コミットで別Agentのレビュー、Cloud検証、GitHub CIを行い、主要な競合と再送はPR専用Previewでも確認する。
