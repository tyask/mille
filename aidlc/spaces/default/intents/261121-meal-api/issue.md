## 目的・背景

P1aで追加したデータ基盤を使い、共有ワークスペースの所属者が献立を記録・閲覧し、過去の献立を再利用できるようにする。P1cの画面が使うHTTP契約を整える。

## 対象範囲・対象外

- ワークスペース配下に、献立の期間一覧・詳細・登録・全置換更新・削除、献立全体のコピー、料理名検索を実装する。
- 既存の認証、同一オリジン確認、献立RepositoryとZodスキーマを再利用する。適用済みの `003_meals.sql` を保持し、コピー・検索・冪等性に必要なDB処理を追加マイグレーションで導入する。
- 献立画面と料理単位のコピー操作はP1cで扱う。本番環境の操作は対象外とする。

## 受入条件

- [ ] AC-01: 期間一覧と詳細を取得でき、登録・更新・削除がそれぞれ `201`・`200`・`204` を返す。一覧は開始日を含み終了日を含まない最大62日間の要約を返す。古い版での更新・削除と埋まっている食事枠への登録・移動は `409` で拒否する。
- [ ] AC-02: 同じワークスペース内で献立全体を別の食事枠へコピーできる。新しい献立・料理・食材のIDを採番し、元の記録を保持する。元の版が古い場合やコピー先が埋まっている場合は `409` を返す。料理名は文字どおりの部分一致で検索でき、同じ料理の別日分を別件として返す。ページ送りのカーソルはワークスペースと検索語に結び付ける。
- [ ] AC-03: 全書き込みで `Idempotency-Key` を要求する。有効な利用者の所属確認後、同じキー・同じ操作・同じ正規化済み入力の再送には24時間、元の成功応答を返す。削除の再送も含めて変更は一度だけ確定し、同じキーで別の操作・入力は `409` で拒否する。変更と再送結果はDBで一括確定する。
- [ ] AC-04: 未認証・利用停止は `401`、不正な書き込み元は `403`、存在しない対象・所属外は `404` を返す。無効な入力は `400`、実受信本文が256 KiBを超える場合は `413` とする。成功・エラー応答を共有キャッシュに載せず、エラーに `error`・`code`・`requestId` を付ける。
- [ ] AC-05: PGliteで空DBからの初期化と003適用済みDBからの増分移行を確認し、HTTP契約テストで権限・競合・ロールバック・再送・入力上限・検索のページ送りを確認する。最終SHAで独立レビューとCloudのlint・型検査・テスト・build・既存のブラウザQAを行う。GitHub CIとPR専用Previewの結果を記録し、主要な競合と再送は専用Previewでも確認する。
