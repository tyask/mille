## 目的・背景

P1a のデータ基盤と P1b の献立 API を使い、家族が同じ共有ワークスペースで献立を記録・編集し、過去の料理を再利用できるようにする。P1 の手動記録と閲覧をスマホ・PC で使える状態にする。

## 対象範囲・対象外

- 献立の週・月表示、朝・昼・夕の詳細、登録・編集・削除、料理名検索、献立全体と料理単体のコピーを実装する。
- 既存の認証・ワークスペース選択と献立 API を使う。料理単体のコピーはコピー先の編集画面で確認してから、通常の登録・更新 API で保存する。画面は設計書のミルフィーユ配色に沿って実装する。
- 献立提案・予定、写真解析、栄養計算は P2 以降で扱う。

## 受入条件

- [ ] AC-01: スマホと PC の週・月表示から日付を選び、朝・昼・夕の未記録・記録済みの状態と献立の詳細を確認できる。料理名検索では同じ料理を作った日ごとに結果を表示する。
- [ ] AC-02: 日付・食事区分・料理名だけで登録できる。複数の料理、人数、食材、分量、レシピ本文または URL を後から編集でき、献立を削除できる。
- [ ] AC-03: 同じワークスペース内の空き枠へ献立全体をコピーできる。料理単体は空き枠や既存の献立に追加できる。人数と分量を保存前に確認でき、コピー元の記録を保持する。
- [ ] AC-04: 同じ共有ワークスペースの家族が献立を確認・編集できる。通信失敗や更新競合でも入力を保持し、最新版を確認できる。同じ送信の再試行で二重登録を防ぐ。
- [ ] AC-05: 最終コミットで独立レビュー、Cloud の高速検査・テスト・ビルド、架空 A/B によるスマホ・PC のブラウザ QA を行う。GitHub CI と正式 PR Preview の結果を同じコミットに照合し、検証記録を PR に残す。
