# P2 献立提案と予定の実装計画

- 日付・朝昼夕・人数・食材・調理時間・料理の系統・自由な要望から複数案を表示する。同じワークスペースの記録済み献立を使って最近の重複を考慮し、履歴が空でも提案できるようにする。
- 追加要望で候補を更新し、現在の条件と変更後の候補を表示する。生成に失敗した場合は入力と直前の候補を保持する。
- 候補を空き枠に予定として保存し、作った内容を確認・編集して記録済みにする。既存予定の置換には明示確認と版の一致を求め、記録済みの献立を保護する。予定は実績履歴から除外する。

既存の献立画面・API・所属確認を再利用し、DBは追加マイグレーションで拡張する。今回はテスト用の提案応答で一連の操作を検証する。実LLM接続に向けた提供元・モデル・データ取り扱い・費用の確認は後続工程とする。

履歴ゼロ、所属外アクセス、通信再送、同時更新、生成失敗をテストし、架空A/Bでスマホ・PCの提案から実績化までを確認する。最終SHAで独立レビュー、GitHub CI、正式PR Previewも確認する。
