# 要件書と設計書の文書保存計画

## 目的

合意した献立要件・画面設計・技術詳細設計をリポジトリへ保存し、今後の実装で参照できるdraft PRを作る。

## 範囲

- docs/requirements.md: 家族共通の朝昼夕、任意人数、P1〜P4と未実装の受入条件。
- docs/design/: 索引、画面設計、技術詳細設計、ミルフィーユ配色のSVG構成図と静的HTML画面資料。
- README.md: 文書への導線。
- このintent: 計画、GitHubに保存したIssue本文の承認時点の原文、別々の承認証拠、検証状況。

アプリ/API/DB実装・適用、認証・依存変更、外部サービス作成、Production操作、操作サンプルの実装コード、PR mergeは行わない。

## 手順と検証

1. 基準mainの完全SHAと既存構成をGitHub経由で確認する。
2. 承認済みの要件・設計原稿をMarkdownへ整理し、主要画面をリポジトリ内の資料として保存する。
3. 相対リンク、JSON例、画面資料の静的構造、秘密値・実データ・実装変更の混入を確認する。
4. 承認と検証の記録を凍結し、文書のみをcommitする。
5. 完全SHAを指定して新しい文脈の別Agentが読み取りレビューする。
6. draft PRを作り、同一HEADのCI・Preview・実行できなかった検証をPRに記録する。

## 実行環境の制約

選択されたCloud環境が起動に失敗した。ローカルcheckout、task:start、依存導入、lint・型検査・テスト・build・ブラウザQAは実行できていない。GitHub APIで最新mainから専用ブランチを作り、既存ファイルを保持するGit treeへ文書を追加する。元のPNGにはアクセスできないため、接続元から取得した画面原稿の静的HTMLとSVG構成図を保存する。JavaScriptを含む操作サンプルは保存しない。

この制約を成功扱いせず、必要な検証が揃わない限りdraftを維持する。凍結後の結果はPR/Issueへ記録する。
