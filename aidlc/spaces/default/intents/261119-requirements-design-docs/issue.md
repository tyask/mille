## 目的・背景

このチャットで確認したmilleの要件、ミルフィーユを意識した画面設計、技術詳細設計をGitで管理し、今後の実装の比較元にする。利用者から要件書と設計書をコミットするPRの作成依頼を受けている。

## 対象範囲・対象外

対象:
- docs/requirements.md：家族共通の朝昼夕、人数任意、段階別要件と受入条件
- docs/design/README.md：設計文書への入口と文書の位置づけ
- docs/design/screen-design.md：画面構成、遷移、ミルフィーユ配色、主要画面モック
- docs/design/technical-design.md：既存構成を踏まえたDB・API・権限・更新競合・再送・AI連携・移行と検証
- docs/design/assets/：献立・提案・PCの画面モック画像
- READMEの文書リンクと、開発ルールに沿うaidlcの記録

対象外:
- アプリ機能、API、DB migrationの実装・適用
- 認証、依存パッケージ、外部サービス、Production、アクセス権の変更
- 一時生成物、ZIP、過去版、検証ログ、操作サンプルの実装コードの保存

## 受入条件

- [ ] AC-01: 認証・ワークスペースの既存実装と、P1手動記録、P2提案、P3写真、P4栄養の計画を区別する。
- [ ] AC-02: 家族共通の朝昼夕と人数任意、個人別摂取量を後回しにする要件を保存し、画面設計と技術設計が整合する。
- [ ] AC-03: ミルフィーユのクリーム・パイ・焼き色を意識した配色と、架空データの画面モックを保存する。
- [ ] AC-04: 技術設計にDB定義・ER図・API/JSON例・権限・更新競合・二重送信・後続機能・移行/検証方針を含め、未実装と提案値を明示する。
- [ ] AC-05: 文書間と画像へのリンクをリポジトリ内で辿れ、/workspaceやlocalhost、個人用Pageだけに依存しない。秘密値や実利用者情報を含めない。
- [ ] AC-06: 文書と追跡記録の変更に限定し、差分・参照リンク・画像・JSON例を確認する。別Agentの読み取りレビューと現在HEADのCI結果をPRに記録する。
