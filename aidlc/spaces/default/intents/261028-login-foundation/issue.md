## 目的・背景
Mille の最初の基盤として、Google ログイン、ログアウト、認証済み利用者だけが表示できる最小ホームを構築する。Cake の技術構成・認証方式・開発手順を踏襲する。

将来は、食事写真と手入力による食材・量の記録、栄養計算、献立履歴とレシピ URL、期間別のグラフ、最近の栄養状態・献立や食材・好みに応じた献立提案、共有ワークスペースを想定する。献立提案を最優先とするが、今回はログイン基盤に限定する。

## 対象範囲・対象外
### 対象
- Cake main d685b029ca8e13d82802e49ac93ac8c720501acf を参考に、Node.js 24.19.0、Next.js 16.2.12、React 19.2.8、TypeScript 6.0.3、Auth.js 5 beta.32、Neon PostgreSQL、Vercel、CSS/CSS Modules の必要部分を採用する。
- Google ログイン、ログアウト、本人情報取得、保護された最小ホーム画面。
- 認証用 app_users と専用 migration。確認済みメールかつ事前登録済み・有効な利用者のみ許可し、自動登録はしない。保護された処理は DB で利用可否を再確認する。
- 初期実利用者は指定を確認して登録する。登録・無効化は接続対象を照合する運用手順を用意する。
- Mille 専用 Vercel と、本番／Preview を分離した Neon 環境。既存資源を確認して重複作成を避け、無料枠を優先する。追加費用は承認を得る。
- Preview 専用の架空テストユーザー A/B。認証テーブルのみへ冪等に登録する。本番ではテスト認証・テストユーザー・テスト seed を拒否する。
- 開発規約、CI、ローカル QA、正式 Preview QA、自己レビュー・別 Agent レビュー、PR と結果報告。
- 開発用 PGlite と正式 Preview 用 Neon を使い分ける。初回 PR は main に未導入の自動化に依存せず、承認済みの正規 CLI/API で Preview を用意する。管理用資格情報をアプリのビルドへ渡さない。

### 対象外
- ワークスペース、招待、共有、管理画面、プロフィール編集。
- 写真解析、食材・栄養 DB、献立履歴、グラフ、LLM、献立提案の実装。
- Cake の家計機能、固定管理者メール、通常利用者 2 名制限、家計用 migration、ワークスペース自動作成処理の移植。
- Cake 本番データ・DB・認証情報の流用や変更。
- 本 Issue の承認のみを根拠とした PR merge、本番反映、新規課金、永続認証情報の発行やアクセス権拡大。

### 実施順
1. 保存済み Issue 本文への承認を受ける。
2. 開発ブランチを作成し、開発規約と最小アプリ、認証 DB、ログイン画面、テストを実装する。
3. 対象・料金・権限を確認したうえで専用環境と Preview テストユーザーを用意する。必要な認証・資格情報の操作は個別承認後に行う。
4. レビュー、最終コミットの CI・Preview 検証を行い、PR を Ready にして結果を報告する。merge と本番操作は別途判断する。

## 受入条件
- [ ] AC-01: 事前登録済み・有効・メール確認済みの Google 利用者だけログインできる。
- [ ] AC-02: 未登録、無効化、メール不一致、改ざん・期限切れセッションを拒否する。既存 JWT でも DB で無効化された利用者を拒否する。
- [ ] AC-03: 保護画面・API で本人と利用可否を確認し、未認証では利用できない。ログアウト後にブラウザ履歴で戻っても保護された情報を利用できない。
- [ ] AC-04: Preview の A/B が独立したセッションで利用できる。再 seed で重複登録や停止状態の自動解除を起こさない。
- [ ] AC-05: Production では設定ミスがあっても、テスト画面・直接認証要求・テスト用 ID・テスト seed を拒否する。
- [ ] AC-06: ワークスペース用テーブルなしで認証が完結し、ワークスペース UI/API/自動作成処理が存在しない。
- [ ] AC-07: Mille 専用資源を照合し、Cake や実ユーザーデータを Preview に流用しない。Preview から本番 DB へのフォールバックを禁止する。
- [ ] AC-08: 最終コミットで lint、型検査、回帰テスト、build、PC/mobile のブラウザ QA、正式 Preview 検証を完了する。実施不能は成功扱いせず理由を報告する。

ブラウザ QA は PC/mobile × A/B でログイン、再読込、本人表示、ログアウト、未認証拒否、セッション分離を確認する。Google の確認フラグ、停止済みユーザー、認証モード、戻り先 URL も回帰テストする。A/B の成功と実 Google OAuth の成功は分けて記録する。
