# AC-03 の停止原因の特定と Cake に沿った Native Preview の完了

[Issue #32](https://github.com/tyask/mille/issues/32) の AC-03 を検証する。A #45 は専用資源の作成前に止まった。後続の削除ジョブは共通の事前照合を通過した。 [A の管理ジョブ](https://github.com/tyask/mille/actions/runs/44985913479/job/137096380387)

信頼済み `main` の管理ジョブに GitHub の作成履歴、Neon の読み取り、Vercel の作成要求などの固定工程と、取得できた HTTP 状態の記録を追加する。既存の Actions 資格情報を使う経路で再現し、特定した原因を修正する。資格情報、接続文字列、例外本文、プロバイダーの応答本文は記録しない。作成結果が不明なときは所有記録と資源を照合する。

Cake と同じ順序で静的デプロイによる分岐、専用 DB とエンドポイントの照合、Native が注入する接続情報によるアプリ公開を行う。DB 初期化と公開の前に PR、現在 HEAD、デプロイ、分岐元、専用接続先と世代、他の接続先からの分離を照合する。同じ PR の HEAD 更新で照合済みの DB・エンドポイント・世代を再利用し、終了時は所有を確認した資源を削除する。 [Cake の実装](https://github.com/tyask/Cake/blob/bc737a52701cc3ddf56a17fb947b8c952a379e22/scripts/preview/preview-service.ts#L50-L135)

照合不一致時の書き込みと削除の停止、同一 PR での DB 再利用をテストし、最終 HEAD の独立レビュー、Cloud 検証、CI、正式 Preview を確認する。試験用 PR 2件で架空データの分離、HEAD 更新後の保持、クローズとマージそれぞれの専用資源削除を実環境で確認する。Native の一時切替と本番デプロイを伴うマージは別途承認を得る。試験後に旧構成へ復旧して常設 Preview と設定を確認し、証拠が揃った時点で AC-03 をチェックする。
