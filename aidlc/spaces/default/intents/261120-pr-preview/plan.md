# Issue #18 実装計画

保存済み Issue とその進捗欄から、今回の作業に必要な手順を記録する。

1. 同一リポジトリの `codex/*` から `main` への PR イベントを受け付ける。通知元の実行と現在の PR、HEAD、状態を、main 管理処理で GitHub API と照合する。
2. PR ごとに mille 専用 Neon DB と Vercel Preview を管理する。mille の migration と架空 A/B 登録を再利用する。更新時は DB を維持し、終了時は所有を照合した PR 専用資源を削除する。
3. 管理資格情報は main に限定し、有効化前に対象、権限、利用枠を確認する。
4. 開発手順に現在 HEAD の URL、CI と正式 Preview の PC・スマホ × A/B、Ready 条件を記載する。
5. 導入 PR のレビュー、CI、回帰検証を行う。別途承認を得てマージされた後、確認用 draft PR で作成・更新・削除を実測する。

## 実装中の記録

受付の実行 ID・世代・現在 PR の SHA と状態を main 上で照合する処理を追加した。PR が受付定義を変更した場合は管理対象にしない。
GitHub のイベント実測、資源管理、有効化前の権限・利用枠照合、導入 PR の最終検証は残っている。

管理処理を接続した。管理ジョブは main 限定 Environment に置き、使用するプロバイダーのプロジェクトを PR 専用に分離する。対象 PR の Git オブジェクトを取り出し、Vercel に送る。PR の更新では既存 Neon ブランチを引き継ぎ、close または merge 時は所有情報が一致する Vercel と Neon の資源を削除する。閉じた PR の通知が発生しない場合の照合付き手動 cleanup を設けた。
