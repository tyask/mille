# mille 要件書

要件整理日：2026年11月19日

本書は献立機能の開発要件を定義する。以下のチェック項目はアプリの完成条件であり、要件書・設計書を保存するPRの完了条件ではない。各機能の実装・検証後に更新する。

## 1 目的と利用形態

家族が共通の献立を記録・共有し、過去の食事を振り返りながら次の献立を決められるようにする。

- 家族で同じワークスペースを利用する。
- 朝・昼・夕を、それぞれ1食として管理する。
- 家族共通の献立と「何人分か」を記録する。人数は任意とする。
- スマートフォン中心で、PCからも利用できるWebアプリにする。
- milleはミルフィーユに由来する。配色はクリーム、カスタード、パイの黄金色、キャラメルの焼き色、チョコレート色を基本とする。

## 2 既存実装と追加範囲

Googleログイン、事前登録済み・有効な利用者の確認、個人用・共有用ワークスペース、切替・招待・メンバー管理は既存実装を利用する。

本書の献立記録、献立提案、写真解析、栄養計算は追加する計画機能である。画面モックや操作サンプルで動くことを、アプリ本体への実装完了とは扱わない。

## 3 記録の基本ルール

1ワークスペース・1日・1食事区分につき、共通の献立を1件持つ。1食には主菜・副菜・汁物など複数の料理を含められる。

アプリの利用者数と料理の人数は別に扱う。食材量は料理全体に使用した量とする。不明な量は未入力として保存し、0として扱わない。「200」「1/2」「少々」などの入力原文を残す。

材料・分量・作り方は、記録した時点の内容を保持する。将来の標準レシピの更新やコピー先の編集で元の履歴を変更しない。利用者が履歴自体を編集することは可能とする。

## 4 開発段階と完成条件

### P1 手動記録と閲覧

- [ ] AC-P1-01: 日付・朝昼夕・料理名だけで保存し、人数・食材・分量・レシピを後から補完できる。
- [ ] AC-P1-02: 複数料理を登録・編集・削除でき、レシピは本文またはURLで保存できる。URLの自動取得は行わない。
- [ ] AC-P1-03: 週表示・月表示で日付を選び、その日の朝昼夕と各料理の詳細を確認できる。
- [ ] AC-P1-04: 料理名で検索でき、同じ料理を複数日に作った場合も日付ごとに見つけられる。
- [ ] AC-P1-05: 過去の1食または料理を同じワークスペース内へコピーでき、元の記録は保持される。
- [ ] AC-P1-06: 家族の別アカウントから確認・編集でき、未記録と記録済みを区別できる。

### P2 献立提案と予定

- [ ] AC-P2-01: 対象日・朝昼夕・人数、使いたい食材、調理時間、料理の系統、自由な要望から複数の献立案を提示できる。
- [ ] AC-P2-02: 履歴があれば最近の重複などを考慮し、履歴がなくても指定条件から提案できる。
- [ ] AC-P2-03: 候補へ会話で追加要望を伝え、現在の条件と変更後の候補を確認できる。
- [ ] AC-P2-04: 候補を予定として保存し、作った内容を確認・修正して記録済みにできる。予定は実績へ自動算入しない。
- [ ] AC-P2-05: 記録済みを提案で自動置換しない。既存予定の置換は確認を挟む。

### P3 写真による入力支援

- [ ] AC-P3-01: 写真を添付し、LLMによる料理・食材・分量の推定結果を確認できる。
- [ ] AC-P3-02: 材料の追加・削除、量・単位の修正ができ、不明のまま保存できる。解析結果で手入力を自動上書きしない。
- [ ] AC-P3-03: 解析失敗時も写真添付と手入力で記録を完了でき、画像は所属者だけが閲覧できる。
- [ ] AC-P3-04: 記録した食材名から料理を検索できる。

### P4 栄養計算

- [ ] AC-P4-01: 食品成分表と対応付け、計算できた材料・分量の範囲で栄養を表示し、未対応・不明・推定を区別できる。
- [ ] AC-P4-02: 料理全量の何人分かを示し、栄養を提案へ反映できる。家族個人の実際の摂取量とは扱わない。

## 5 品質と共有の条件

- [ ] AC-Q-01: 画面・API・検索・画像・AIへ渡す履歴に、現在の利用可否と所属の確認を適用する。
- [ ] AC-Q-02: 同じ食事枠の重複、古い内容による上書き、通信再試行による二重確定を防ぐ。
- [ ] AC-Q-03: 保存・取得・生成の失敗時は入力や条件を保持し、再試行または手入力へ進める。
- [ ] AC-Q-04: スマホ・PCで主要操作を利用でき、予定・記録済みを色だけに頼らず区別できる。

## 6 対象外と設計上の提案

個人別の食事・取り分・摂取量、買い物リスト、在庫管理、リアルタイム共同編集、公開レシピ検索は今回の要件に含めない。

件数・容量・期限・応答時間の数値上限、LLM提供元、画像保存先、食品成分表の選定は技術設計上の提案・選定事項であり、合意済みの業務要件と区別する。写真の対象・形式もP3の実装計画で確定する。
